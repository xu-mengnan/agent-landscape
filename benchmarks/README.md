# 真实模型评估任务集（未执行）

35例、7类，每例包含输入、合成状态、工具范围、故障干预和独立验收目标。文件是研究设计，不是运行结果。计划三次重复、四个方案共420次；本轮执行数为0。

## 文件

- `cases/evaluation.jsonl`：评估候选集v0.1，35例。
- `cases/long-context.txt`：500条合成干扰记录，实际适配时按案例把它插入历史。
- `configs/planned-comparison.json`：刻意保留未配置的模型/预算，不能直接触发付费调用。
- `graders/README.md`：评分器合同。

## 正确使用顺序

冻结版本与预算，写真实SDK适配器，为每个任务实现模拟工具及环境终态检查，另建不重用评估题目的开发集，验证评分器，再运行正式集。不能看到评估失败后专门修改该题提示并保留原成绩。

只把`public_input`送入模型；`private_evaluator`必须留在评分侧。工具名字只是契约，不是已实现的厂商API。必须将权限由宿主身份实施，不能把initial_state里一段文字当权限系统。

## 独立产品组

通用研究产品做多源资料整合/修订/产物验收；编码产品使用相同测试仓库、冻结测试与任务。不跨组混排。产品卡给出建议任务但没有登录运行结果。

## 与离线30项检查的区别

`experiments/`验证原创代码机制，没有模型、Agent SDK或产品执行。即使其全部通过，也不能把这里35个任务标记为完成。正式适配器与逐场景评分器尚未实现，本包不提供虚假的成功率。

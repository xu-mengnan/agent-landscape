# MCP、A2A、Skills：三个接口问题，不是一套安全系统

## 文档定位

|对象|主要解决的问题|本轮证据|
|---|---|---|
|MCP|模型应用与工具、资源、提示等能力交换|latest入口解析至2026-07-28规范 [S28]|
|A2A|独立Agent服务之间的发现、任务与结果协作|官方规范入口 [S29]|
|Agent Skills|把可复用任务说明与附属资源按需提供给Agent|SKILL.md与渐进式加载说明 [S30]|

当前MCP规范还区分可选扩展。协议版本、扩展支持与具体客户端实现必须分别记录，不能拿旧版本生命周期知识直接套用到新规范。[S28]

## 原创组合示例（I）

一个研究Agent加载“来源审阅”Skill，通过MCP访问被授权的文档检索工具，再通过A2A把独立子任务委派给另一个团队的Agent服务。三个机制分别回答“怎么做”“如何访问工具”“如何协作”，但都不能自行授予读取私有数据或执行交易的权利。

## 几个容易误判的地方（I）

读取Skill内容不等于授权执行其脚本；工具描述也不是可信系统指令。外部文档和远端Agent结果都应按不可信输入处理。具备A2A任务状态不能推出远端业务动作与本地事务原子提交；具备MCP工具列表不能推出所有工具都应交给模型。

渐进式加载可以减少初始上下文，但发现描述质量、错误选择、版本变化和路径权限仍需测试。不要将脚本加载来源自动提升为管理员权限。

## 互操作验收

冻结客户端/服务端版本；显式记录协商的扩展；用不可用能力、拒绝访问、取消、重复请求和恶意描述进行测试。把“能建立连接”“能交换正确Schema”“能安全完成业务”分成三档结果。本轮只做文档定位，没有运行互操作测试。

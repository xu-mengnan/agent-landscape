# DeepSeek Harness / Cordis：插件组合、持久事实与运行时事件

**D；读取上游README、架构章节和安全声明；不是完整源码审计。** 上游仍明确标注开发者预览与潜在兼容性破坏。[S16]

## Cordis在这里承担什么

D｜架构文档将服务、类型化事件和可撤销注册效应放在共享上下文中，模型、工具、会话及Agent loop等可通过插件组合替换。Profile和bundle表达启动组合及覆盖层，而不是业务任务DAG。[S17]

I｜因此，Cordis解决的是组件生命周期、依赖与扩展组合问题；Agent运行过程负责模型与工具交互；业务状态机又是另一层。不能把这三者统称“多Agent框架”后忽略它们不同的状态范围。

## 从模型调用到工具结果

D｜已读架构章节区分持久SessionEvent、运行中Agent事件和能力扩展事件；模型上下文由日志投影形成。架构明确指出，硬进程丢失若发生在一次尝试持久落定之前，不会留下完整持久尝试流。[S17]

I｜值得借鉴的是“模型实际看到的上下文可追溯”，以及将运行时通知与可恢复事实分开。前者便于排查摘要/检索误差，后者避免把内存事件当可靠消息。

## 不能混淆的三个边界（I）

**插件卸载清理≠外部业务回滚。** 清理监听器、服务注册或资源引用，不能自动撤回已发送通知、已写订单或已执行远端命令。真正补偿需要业务定义。

**会话事件落盘≠任意时刻精确续跑。** 仍需区分输入持久化、模型流结算、工具请求写入、接收方生效、返回写入的不同阶段。

**可替换能力≠替换后语义兼容。** 切换文件系统或工具后端时，应验证路径、权限、超时、取消和错误契约是否仍一致，旧会话是否能解释新结果。

## 安全状态

D｜上游SAFETY明确说明实验性质、尚未安全审计，不能视为安全或生产就绪；沙箱、审批和权限只能降低风险，不应成为不可信工作负载的唯一防线。[S18]

I｜本项目建议将其用于隔离环境中的架构学习和局部机制PoC，而不是未经验证承担关键业务写入。这个判断依据明确的预览安全声明，不是对模型能力的评价。

## 可借鉴设计（I）

在自有系统中可以先实现稳定的工具执行接口、事件事实模型、日志投影和插件生命周期清理测试，不必一次替换整条链路。插件应声明依赖、权限与输出契约；启动时缺少关键服务应显式失败，而非静默降级成不一致行为。

## 后续实测边界

隔离环境中再验证插件卸载后的残余监听、日志损坏、硬退出前后事件边界、版本迁移和沙箱越界。当前没有运行dsh或Cordis，也没有据此给出执行成功率。

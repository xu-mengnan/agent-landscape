# Google ADK 2.0：工作流能力与事件迁移必须一起评估

**D；未安装运行。** 核验的是2.0版本系列，而非未验证的最新补丁。

## 文档确认

D｜ADK 2.0页面列出图式、动态及协作工作流；Python与Go的GA日期分别为2026-05-19和2026-06-30。[S13]

D｜迁移说明涉及执行层次、事件结构和输出字段变化；手动写session事件、依赖内部类覆写及过宽异常处理，都可能影响新的执行流程。[S13]

## 工程含义（I）

选择图式还是动态编排不应只看写代码是否简洁。图式更适合显式前置条件和路径审核；动态控制可以表达更复杂的运行期循环；协作式需要额外定义调度与结果仲裁。三者可以针对不同子问题采用，而不是全系统只允许一种。

事件结构变化会穿透日志、数据库校验、重放、评测和监控面板。升级SDK时如果只修改Agent构建代码，却没有升级事件消费者，可能出现任务看似运行但审计和恢复信息缺失。

## 迁移检查设计（I）

1. 保存一组旧版本合成会话、事件和检查点作为固定夹具。
2. 新读取器先验证能否识别旧格式；无法转换时显式拒绝，不静默丢字段。
3. 完成读取兼容后再发布新格式写入器，并为事件记录schema版本。
4. 对业务异常、可重试基础设施异常和取消信号分别测试，避免统一catch后返回“成功”。
5. 使用公开接口扩展，依赖内部实现的覆写单独列入升级风险表。

以上是本项目设计，不表示ADK对所有旧历史提供无缝升级保证。

## 采用判断（I）

对需要代码化图流程及语言路线选择的团队，ADK是值得加入验证的候选。已有Google相关基础设施可以作为集成条件，但不能把“生态熟悉”当成故障恢复或任务质量证据。

与其他SDK对照时，首先确认同一个模型、同一套工具和相同重试策略能够在各适配器下运行。无法统一时，将差异公开列出，或者移动至原生能力测试，不能混在一个成绩表中。

## 尚未验证

高并发会话隔离、跨版本恢复、并行写状态、模型供应商兼容、实际吞吐和费用均未实测。正式入选需要通过流程合法性、超时/取消和持久恢复三个门槛。

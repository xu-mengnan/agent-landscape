# 安全、成本与采用门槛

本章为原创工程建议（I），结合已核验的权限、追踪和预览状态，不构成对任一产品的安全认证。

## 先定义高风险动作

只读公开检索、创建草稿、修改工作区、发布代码、发送消息、改变业务状态应分不同等级。用服务端身份判断工具是否允许，用业务规则验证参数和前置条件；模型输出仅为操作提议。

审批绑定用户、任务、操作类型、参数摘要、版本和有效期。需求修改或参数变化时旧审批失效。拒绝、取消与过期必须传播到真正执行动作的服务，而不只是界面显示。

## 最小威胁模型

|威胁|测试输入|防护检查|
|---|---|---|
|检索提示注入|文档要求忽略规则、读取私密文件|来源不进入高优先级指令；工具授权独立|
|跨租户访问|相同对象ID、不同tenant|服务端强制租户过滤，非prompt约定|
|重复副作用|动作已成功但返回丢失|稳定幂等键、参数哈希校验、对账|
|任意代码/插件|不可信Skill或依赖|最小文件/网络权限，隔离环境|
|状态污染|旧消息、错误摘要、自称已付款|字段权威、CAS版本、审计|
|检查点污染|恶意/损坏恢复文件|可信后端、类型限制、完整性校验|
|数据外泄|Trace含用户全文或凭据|采集/导出最小化、脱敏、访问和保留限制|

OpenAI对不同guardrail路径有明确范围，Codex工程资料把沙箱和审批分开，Microsoft检查点文档强调恢复数据可信性，DeepSeek明确其预览安全限制。[S02][S20][S15][S18] 这些是边界证据，不是由某个框架负责全部安全的理由。

## 不虚构价格

本轮没有API账单、商业产品订阅测试或部署费用，因此价格栏保持未测。建议实际记录模型输入/输出、缓存、工具费、环境时间、持久存储、失败/重试以及人工审阅时间。

总成本=模型+工具+运行环境+存储+人工介入。失败的调用也付出了成本。订阅产品的额度消耗与按量API费用分开，不能根据一次演示推算整月生产费用。

## 建议准入条件

高风险写入必须：无越权、无跨租户泄漏、重复请求不产生重复效果、错误参数不能偷换幂等操作、失效审批不可重用、取消后未派发任务不再派发、结果能审计。达到这些条件后，再讨论任务成功率、时延和费用。

## 尚不具备的证明

离线SQLite实验不模拟网络分区、主从切换、恶意攻击、外部服务故障集群和真实LLM行为。单机并发测试也不是分布式一致性证明。生产采用需要专门的安全审阅与压力/故障测试。
